# タイプ別プレイガイド

## 目的

診断結果を「タイプ名を知って終わり」にせず、次の試合で試せる行動へつなげます。

同時に、8タイプを診断結果URL以外からも閲覧できる公開コンテンツとして提供します。

## 公開ルート

```text
/types
/types/<typeId>
```

`/types`は8タイプの一覧、`/types/<typeId>`はタイプごとの詳細ガイドです。

個人の回答トークンを含まない公開コンテンツのため検索対象とし、sitemapへ一覧1件・詳細8件を掲載します。

## コンテンツ構成

各タイプは次を必須とします。

- タイプ概要
- 強み3件
- 注意点
- 得意を出しやすい状況3件
- 崩れやすい状況3件
- やりがちな失敗3件
- 3段階の練習メニュー
- 試合後の振り返り質問3件

練習メニューは次の順序です。

1. `まずは`: 1つの観察・行動へ絞る
2. `次に`: 判断後のつなぎや切り替えを加える
3. `慣れたら`: 状況に応じて判断を変える

## データ設計

ガイドは`data/resultGuides.ts`へ定義します。

結果タイプの判定条件は`data/resultTypes.ts`に残し、コンテンツとスコアリング責務を分離します。

`lib/resultGuide.ts`が両者を`resultTypeId`で結合します。

この構成により、文章の更新だけで診断判定が変わることを防ぎます。

## 診断結果ページ

結果ページでは、該当タイプのガイドから次だけを抜粋します。

- ガイドの要約
- 最初の練習メニュー
- 得意を出しやすい状況2件
- 崩れやすい状況2件
- 詳細ページへのリンク

長い解説は公開詳細ページへ分離し、診断結果ページの情報量が増えすぎないようにします。

## コンテンツ方針

### 扱う内容

- 開戦判断
- 人数差
- 味方との距離
- 視界・ウェーブ・オブジェクト準備
- 位置取り
- 戦闘後の切り替え
- 試合後の振り返り

### 扱わない内容

- 特定パッチの数値
- 最新Tier
- ビルド・ルーン・アイテムの固定推奨
- チャンピオン個別攻略
- Riot API由来データ
- 勝率が上がることの保証

パッチで大きく変化しにくい、プレイヤーの判断と行動に関する内容を優先します。

## 表現上の注意

タイプ間に優劣は設けません。

`崩れやすい状況`や`やりがちな失敗`は人格や能力の欠点ではなく、そのプレイスタイルを強く出したときに判断が偏りやすい条件として記述します。

また、練習メニューは特定ロールを前提にせず、複数ロールで試せる内容を優先します。

## 検証

```bash
bash scripts/check-type-guide-files.sh
npm run test
npm run build
npm run smoke:standalone
```

単体テストでは次を確認します。

- 結果タイプ8件
- ガイド8件
- 欠落なし
- 未知IDなし
- 重複IDなし
- 各コンテンツが3件
- 練習順序が`まずは`→`次に`→`慣れたら`
- 不正typeIdの参照がnull

standaloneスモークでは次を確認します。

- `/types`がHTTP 200
- sitemapに`/types`が存在
- sitemapにタイプ詳細が8件存在
- 全8詳細ページがHTTP 200
- 全詳細ページに主要4セクションが存在
- 一覧・詳細ページが`noindex`ではない
- 不正typeIdがHTTP 404
- 共通セキュリティヘッダー

## 更新時の注意

結果タイプを追加・削除する場合、`data/resultTypes.ts`と`data/resultGuides.ts`を同じPRで更新してください。

片方だけ更新すると`tests/resultGuide.test.ts`が失敗します。

ガイド文章だけを調整する場合は、スコアリング条件を変更する必要はありません。
