# 診断履歴・前回比較

## 目的

再診断したユーザーが、結果タイプだけでなく8軸スコアの変化を振り返れるようにします。

アカウント登録やサーバー保存は行わず、現在の静的・VPS構成を維持します。

## 保存先

診断結果はブラウザの`localStorage`へ保存します。

```text
lol-type-choice.result-history.v1
```

- 保存先は現在のブラウザ・端末のみ
- サーバー送信なし
- 複数端末同期なし
- シークレットモードやブラウザ設定によっては保存不可
- ブラウザデータ削除時に履歴も削除

保存できない場合でも、診断結果の表示・X共有・結果URLの利用は継続できます。

## 保存データ

1件ごとに以下だけを保存します。

- `schemaVersion`
- 記録ID
- 診断日時
- 結果タイプID・名称
- 8軸スコア
- おすすめロール上位2件
- 結果を再表示する相対URL

チャンピオン推薦全文、ユーザー名、メールアドレス、IPアドレス、Cookieは保存しません。

## 保存ルール

- 最大10件
- 新しい結果を先頭へ追加
- 11件目追加時は最古の結果を削除
- 同じ回答結果を連続して開いただけの場合は重複保存しない
- 別の結果を挟んで再度同じ結果になった場合は、新しい診断として保存

## データ検証

読み込み時に以下を検証し、不正な項目は読み飛ばします。

- `schemaVersion`が現在の値と一致
- 記録IDの形式
- 診断日時が有効
- 結果タイプID・名称の長さ
- 8軸がすべて存在
- 各スコアが0〜100の整数
- ロールがTOP・JG・MID・ADC・SUPのいずれか
- 結果URLが`/result?r=...`形式
- 回答トークンのバージョン・件数・チェックサムが有効
- 重複した記録IDがない

外部URL、追加クエリ、ハッシュ、不正な回答トークンは履歴リンクとして採用しません。

## 画面

### 結果ページ

診断完了後に結果を自動保存します。

前回と異なる結果が存在する場合、8軸すべてについて次を表示します。

- 前回スコア
- 今回スコア
- 増減値
- 前回結果へのリンク

### 履歴ページ

```text
/history
```

- 保存件数
- 経験した結果タイプ数
- 最新診断日時
- 各履歴の結果タイプ
- おすすめロール
- 上位3軸
- 結果再表示
- 個別削除
- 全削除

履歴ページは`noindex`・`nofollow`とし、robots.txtでもクロール対象外にします。sitemapには追加しません。

## Analyticsイベント

- `result_history_saved`
- `result_history_opened`
- `result_history_viewed`
- `result_history_reopened`
- `result_history_deleted`
- `result_history_cleared`

履歴の8軸値や結果URLはAnalyticsへ送信しません。

## 確認方法

```bash
bash scripts/check-result-history-files.sh
npm run test
npm run build
npm run smoke:standalone
```

手動確認:

1. 診断を完了し、結果ページに初回保存メッセージが出る
2. 同じ結果URLを再読込して件数が増えない
3. 別回答で診断し、前回との差分が表示される
4. `/history`で両方の結果を確認する
5. 過去結果を再表示する
6. 個別削除する
7. 全削除する
8. localStorageを不正JSONへ変更しても画面が壊れない

## 対象外

- サーバー同期
- アカウント連携
- クラウドバックアップ
- 履歴データのインポート・エクスポート
- 履歴の公開共有
- 行動改善の自動評価
